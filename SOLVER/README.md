# Воспроизводимые прохождения

Стенд находится только в `continued`. Игра и её ресурсы собираются Turbo Pascal 7.0. Python здесь управляет поиском решений на современном компьютере; он не входит в игру.

В Windows все процессы стенда используют одни и те же два логических процессора с пониженным приоритетом. Поиск и DOS-проверки запускаются последовательно.

`ROUTES/` хранит полные последовательности клавиш на максимальной сложности, сид, задержки ввода, конечное состояние и найденные механики. Данные кампании, деньги, армия и результаты боёв в игру не подставляются. Поиск читает память, откатывает локальные снимки и перебирает варианты. В готовой записи остаётся только выбранная последовательность ввода.

Референс — ревизия `cedabcca6bd3b2a19c55b0a778fe6ad2057fba8c`, первая с поддержкой сида. В стенде сид устанавливается непосредственно перед генерацией новой кампании. Одного начального значения недостаточно: случайные события зависят также от времени подачи клавиш, поэтому сохраняется число пустых опросов клавиатуры.

## Подготовка

Нужны Python 3, DOSBox-X и компилятор из `PASCAL/`. Из корня репозитория в PowerShell:

```powershell
python -m venv .git/kb2-solver-host
.git/kb2-solver-host/Scripts/python.exe -m pip install -r SOLVER/requirements.txt
$env:KB2_DOSBOX = 'C:\path\to\dosbox-x.exe'
.git/kb2-solver-host/Scripts/python.exe SOLVER/build.py
```

Сборки и временные результаты находятся в `.git/kb2-solver/`; каталог можно изменить переменной `KB2_SOLVER_WORK`. Ресурсы собираются из PCX и остальных исходников, готовая игра не используется. Сборка создаёт быстрые поисковые программы `CUR/REF`, DOS-программы с исходной графикой `DOSCUR/DOSREF` и обычные интерактивные программы `PLAYCUR/PLAYREF`. Последние запускаются из соответствующего `DATA/` командой `..\CODE\SEEDED.EXE 1`. Для интерактивного запуска задайте фиксированные 3000 cycles: проблема CRT на высокой частоте отмечена в `BUGS.md`.

## Поиск

```powershell
.git/kb2-solver-host/Scripts/python.exe SOLVER/solve.py --seed 12345
.git/kb2-solver-host/Scripts/python.exe SOLVER/search.py --seed 1 --scenario workshop
.git/kb2-solver-host/Scripts/python.exe SOLVER/search.py --seed 2 --scenario magic
```

Экономический поиск накапливает доход, использует пергаменты, открывает острова, покупает пять частей карты и корабль, затем достигает финала первой серии. Расширенные стратегии добавляют бои, замки, торговлю, подземелья, ритуалы, создание воинов и магию. Проход по местности строится с учётом работ; перемещения волшебника и варианты его предложений предварительно отсеиваются моделью генератора случайных чисел, затем проверяются выполнением кода игры.

Промежуточные записи сохраняются в `SEARCH/`. Продолжение: `SOLVER/search.py --seed 2 --scenario magic --resume <путь-к-записи>`. Локальные снимки в `SNAPSHOTS/` позволяют сразу продолжать с сохранённого места. Они привязаны к записи, EXE и реализации исполнителя; в репозиторий не входят. После удаления снимка префикс потребуется исполнить один раз.

## Подтверждённые результаты

```powershell
.git/kb2-solver-host/Scripts/python.exe SOLVER/catalog.py
```

Эта команда читает готовые записи и подтверждения, **не запускает игру**. Она показывает количество вводов, сиды, покрытые семейства механик, самый короткий сохранённый маршрут и минимальное покрытие среди подтверждённых маршрутов. Минимум определяется полным перебором комбинаций; глобальная кратчайшая стратегия игры не утверждается. Открытые семейства выводятся отдельно. Вызов процедуры сам по себе не доказывает успешного применения механики.

В каталоге 59 семейств: развитие кампании и экономика, рабочие и местность, волшебник, острова и море, набор и управление армией, бой и резерв, замки и гарнизоны, торговля, подземелья, королевские задания, ритуалы и реликвии, создание воинов, все 13 свитковых заклинаний и «Дар», поражение с продолжением, сохранение с загрузкой, справка и финал. Это покрытие игровых возможностей, а не всех ветвей кода, случайных событий, типов существ и сочетаний их свойств.

Для нового маршрута достаточно одной независимой проверки:

```powershell
.git/kb2-solver-host/Scripts/python.exe SOLVER/native_replay.py SOLVER/ROUTES/seed-1-workshop.json
```

Проверка сравнивает все 46 816 байт кампании и состояние генератора на границах ходов с обеими DOS-сборками, с исходным кодом графики и обычным циклом опроса клавиатуры. Проверяется достижение финала и нормальный выход. Подтверждение `.proof.json` сохраняет хеши записи, EXE и последовательности состояний. При совпадении записи и EXE команда использует готовое подтверждение. Повторение требует явного `--force`.

`replay.py` — отдельный диагностический инструмент сравнения быстрых сборок, `coverage.py` — счётчики посещения процедур. Они не являются дополнительными обязательными прогонами после успешной DOS-проверки.

Скорость этого поиска не является измерением скорости игры на 286: графика, звук и задержки в поисковой сборке пропущены, DOS-проверка также отключает ожидания. Измерения производительности находятся отдельно в `BENCH/`.

Запись с `sessions` включает несколько запусков: кампания сохраняется самой игрой, процесс завершается, следующий процесс читает созданный файл. Готовые сохранения к маршруту не прилагаются. `save_reload.py <префикс> <результат>` строит такое продолжение; `recovery.py` содержит цели для резерва, поражения и морского перехода, `spirit.py` — для реликвий и вызова духа. Эти цели можно добавлять перед финалом в `search.py`.
